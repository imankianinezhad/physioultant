# Security & Privacy Notes – v1.7.0
**Architecture:** static site (Cloudflare Pages `public/`) + one serverless function `functions/api/analyze.js`. The Google Gemini key is the Cloudflare secret `GEMINI_API_KEY`; it is read only inside the function and sent only in the `x-goog-api-key` header to generativelanguage.googleapis.com. It is never in the repo, the page, the CSP-allowed browser code or responses.
**Controls implemented:** CSP (script by SHA-256 hash, `connect-src 'self'`, no forms/base); function accepts only POST with `Origin` in ALLOWED_ORIGIN, JSON only, body ≤12 KB, text 15–8000 chars, language whitelist; patient text is wrapped in `<patient_text>` and treated as data (prompt-injection mitigation); model output is schema-constrained and re-validated server-side (enum whitelists, length clips) and rendered with HTML escaping on the client; upstream errors are never forwarded; the function does not log request text or the key; optional `RATE_LIMITER` binding; responses `Cache-Control: no-store`.
**Rule-based red-flag screen** (EN/FA/FR regex) runs independently of the AI, but it is a simple safety net, not clinical triage.
**Privacy facts:** speech recognition runs in the browser vendor's service (e.g. Chrome sends audio to Google); the confirmed text is sent to our function and to Google's Gemini API. Google's terms for the Gemini API differ between free and paid usage (the free tier may allow use of content to improve products) – **check the current terms and use a paid/billing-enabled project if you will process health text**. Selections, pain types and reports stay in the browser. localStorage keys: `pxc`, `pxs` (country/city/display settings/sex preference).
**Operational must-dos:** (1) never commit keys; if a key was ever pasted in chat/email/issues, revoke and recreate it; (2) restrict the key to the Gemini API in Google Cloud and set quota/budget alerts; (3) add a Cloudflare WAF rate-limit rule for `/api/analyze` (e.g. 10 requests per 10 minutes per IP); (4) keep GitHub 2FA, secret scanning and push protection on; (5) re-test after every change.
**Residual risks:** Origin check is not authentication (non-browser clients can spoof it) – rate limiting and quotas are the real abuse control; `style-src 'unsafe-inline'`; localStorage shared per origin; third-party sites log queries; AI summaries can be wrong; AI/health software may be regulated in some jurisdictions (not legal advice – check); no pen-test. No compliance claimed.
